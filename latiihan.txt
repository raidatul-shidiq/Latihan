RANGKUMAN PELATIHAN GIT, GITHUB, DAN MARKDOWN

1. Version Control & Git
Version Control adalah sistem untuk melacak dan mengelola perubahan file dari waktu ke waktu. Terdapat 3 jenis utama:
- VCS Lokal: Menyimpan riwayat perubahan di komputer sendiri. Contoh: RCS.
- VCS Terpusat (Client-Server): Menyimpan semua versi file di satu server pusat. Risiko: jika server rusak, seluruh project bisa hilang. Contoh: CVS, Subversion.
- VCS Terdistribusi (Peer-to-Peer): Setiap komputer memiliki salinan lengkap dari keseluruhan repository. Risiko data hilang lebih kecil. Contoh: Git, Mercurial.

Git adalah VCS terdistribusi yang gratis, open source, dan paling banyak dipakai. Git memudahkan pelacakan perubahan, kolaborasi jarak jauh, serta branching (membuat cabang) dan merging (menggabungkan).

--- Perintah Konfigurasi Git ---
* `git config --list`: Menampilkan pengaturan Git.
* `git config <key> <value>`: Mengubah nilai variabel.

--- Perintah Dasar & Menyimpan Perubahan ---
* `git init`: Mengubah folder menjadi repository Git.
* `git clone`: Menyalin repository dari tempat lain.
* `git status`: Mengecek status repository.
* `git add <file>`: Menambahkan file ke staging area.
* `git commit -m "pesan"`: Menyimpan perubahan beserta pesannya.
* `git commit -am "pesan"`: Menyimpan semua perubahan (langsung melewati staging).

2. GitHub & Remote Repository
Remote repository adalah salinan pekerjaan kita di tempat lain (internet/jaringan). GitHub adalah platform hosting paling populer untuk menyimpan repository Git secara online.

--- Perintah Menggunakan Remote ---
* `git remote`: Menampilkan semua remote server.
* `git remote add <nama> <url>`: Menambahkan remote baru (contoh: origin).
* `git push <nama-remote> <nama-branch>`: Mengupload commit ke remote (GitHub).
* `git fetch <nama>`: Mendownload data dari remote.
* `git pull <nama-remote> <nama-branch>`: Mendownload dan langsung menggabungkan data dari remote ke branch saat ini.

--- Perintah Membatalkan & Melihat Riwayat ---
* `git reset`: Membatalkan penambahan ke staging area.
* `git reset HEAD~1`: Membatalkan commit terakhir (perubahan tetap ada).
* `git log`: Menampilkan riwayat commit.
* `git log --oneline`: Menampilkan riwayat dengan lebih ringkas.

3. Markdown, Branching, dan Merging
Markdown adalah format dokumen yang praktis dan disukai programmer, sering dipakai untuk membuat file README di GitHub.
- Judul/Heading: Pakai simbol `#` sebelum teks.
- Teks tebal & miring: Pakai `**teks**` (tebal) atau `*teks*` (miring).
- List/Daftar: Pakai angka (`1.`) atau tanda hubung (`-`).
- Link & Gambar: Pakai `[teks](url)` untuk link, dan `![teks](url)` untuk gambar.

--- Perintah Branching & Merging ---
* `git branch <nama>`: Membuat cabang (branch) baru.
* `git switch <nama-branch>`: Beralih ke branch lain.
* `git merge <nama-branch>`: Menggabungkan branch lain ke branch saat ini.
* `git rebase <nama-branch>`: Menggabungkan commit ke branch lain dengan riwayat yang lebih bersih.
